# Phase 5 — PAIMANA Knowledge & RAG Layer Documentation

## 1. Overview & Objectives

Phase 5 of **Project Nirman (PAIMANA AI Infrastructure Monitoring Platform)** establishes a production-grade, citation-aware **Document Intelligence & RAG Retrieval System** across 10 years of PAIMANA PDF reports (2017–2026).

Before introducing Large Language Models (LLMs) in Phase 6, Phase 5 guarantees that the underlying retrieval engine reliably locates the exact source documents, page numbers, reporting dates, and project codes for any infrastructure question.

## 3. Extraction & Semantic Chunking Strategy

### Text Cleaning & Chunking Parameters
- **Extractor**: PyMuPDF (`fitz`) for fast C++ level PDF parsing.
- **Target Chunk Size**: 800 characters (~120–150 words).
- **Chunk Overlap**: 150 characters (~25–30 words) to prevent context fragmentation across boundaries.
- **Project Code Regex**: `\b([0N]\d{8})\b` matching both legacy 9-digit numerical codes (e.g., `020100044`) and modern alphanumeric project codes (e.g., `N04000073`).

### Chunk Metadata Enrichment
Every extracted chunk includes:
- `chunk_id`: Unique identifier (`{source_file}_p{page}_c{chunk_idx}`)
- `source_file`: Basename of PDF report
- `page_number`: 1-indexed page number
- `reporting_month`: YYYY-MM
- `document_type`: Classification tag
- `project_code`: Primary identified project code (if present)
- `project_codes`: All project codes referenced within chunk/page

## 4. Dense Embeddings & Hybrid Retrieval Architecture

```
                             User Search Query
                                    │
                                    ▼
                          FastAPI REST Endpoint
                     GET /api/documents/search?q={query}
                                    │
                                    ▼
                          Metadata Pre-Filter
               (project_code, reporting_month, document_type)
                                    │
                                    ▼
                ┌───────────────────┴───────────────────┐
                ▼                                       ▼
       Dense Vector Cosine                      Lexical Term Frequency
 (TF-IDF + SVD 384-dim / MiniLM)               (Keyword & Project Code)
                │                                       │
                └───────────────────┬───────────────────┘
                                    ▼
                         Reciprocal Rank Fusion
                    RRF(d) = 1/(60+r_vec) + 1/(60+r_lex)
                                    │
                                    ▼
                          Top-K Retrieved Chunks
                    with Verifiable Source Citations
```

### Vector Encoder Specification
The production PostgreSQL database stores 384-dimensional normalized float vectors generated by `EmbeddingService` (`backend/app/services/embedding_service.py`).
- **Primary / Production Vector Encoder**: TF-IDF Vectorizer (20,000 features, 1-2 n-grams) + TruncatedSVD (384 components, fitted on 331,206 chunks). Model saved at `models/embeddings/tfidf_svd_encoder.joblib`.
- **Pre-trained Deep Learning Encoder**: `SentenceTransformer("all-MiniLM-L6-v2")` (384 dimensions). Standardized interface allows hot-swapping encoders without schema migration.

### Reciprocal Rank Fusion (RRF)
To achieve maximum precision across both technical project codes and semantic text queries, we combine vector similarity and lexical term matching using RRF:
$$RRF(d) = \frac{1}{60 + \text{Rank}_{\text{vector}}(d)} + \frac{1}{60 + \text{Rank}_{\text{lexical}}(d)}$$

## 5. PostgreSQL Database Schema (`document_chunks`)

```sql
CREATE TABLE IF NOT EXISTS document_chunks (
    id SERIAL PRIMARY KEY,
    chunk_id VARCHAR(150) UNIQUE NOT NULL,
    content TEXT NOT NULL,
    embedding REAL[],
    source_file VARCHAR(255) NOT NULL,
    relative_path VARCHAR(500),
    page_number INT NOT NULL,
    reporting_month VARCHAR(10) NOT NULL,
    reporting_year VARCHAR(20),
    project_code VARCHAR(50),
    document_type VARCHAR(50),
    metadata JSONB,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_doc_chunks_project_code ON document_chunks(project_code);
CREATE INDEX idx_doc_chunks_rep_month ON document_chunks(reporting_month);
CREATE INDEX idx_doc_chunks_doc_type ON document_chunks(document_type);
```
